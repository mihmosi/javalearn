🔷 Основы дженериков

Что такое дженерики (Generics) в Java?

Краткий ответ: Дженерики — это механизм Java, позволяющий создавать классы, интерфейсы и методы, параметризованные типами. Они обеспечивают типобезопасность на этапе компиляции и устраняют необходимость явного приведения типов.

Проблема до дженериков

List list = new ArrayList();
list.add("Hello");
list.add(42);        // Можно добавить что угодно!
String s = (String) list.get(1); // ClassCastException в runtime!

С дженериками

List<String> list = new ArrayList<>();
list.add("Hello");
// list.add(42); // Ошибка компиляции!
String s = list.get(0); // Без cast!

Ключевые концепции: параметризованные классы/интерфейсы/методы, ограниченные типы, wildcards, type erasure. Правило PECS. Ограничения: нет примитивов, нет new T(), нет instanceof с параметризованными типами.

🟠 Type Erasure

Что такое type erasure (стирание типов)?

Краткий ответ: Type erasure — механизм реализации дженериков, при котором информация о типах-параметрах удаляется компилятором после проверки. В байт-коде List<String> и List<Integer> — один и тот же List.

List<String> strings = new ArrayList<>();
List<Integer> integers = new ArrayList<>();
System.out.println(strings.getClass() == integers.getClass()); // true!

Последствия type erasure

// Нельзя использовать примитивы
// List<int> list; // Ошибка!
// Нельзя создавать экземпляры T
// T t = new T(); // Ошибка!
// Нельзя использовать instanceof с дженериками
// if (obj instanceof List<String>) { } // Ошибка!
// Нельзя создавать массивы дженериков
// List<String>[] array = new List<String>[10]; // Ошибка!
📌 Резюме для Middle+

Type erasure — фундаментальный механизм Java. Компилятор проверяет типы, затем удаляет информацию о них, заменяя T на Object (или верхнюю границу), и вставляет cast'ы. Причина выбора — обратная совместимость с кодом до Java 5.

🟡 Массивы и ограничения

Можно ли создать массив дженерик-типа?

Краткий ответ: Нет, нельзя. Компилятор запрещает new T[], new List<String>[]. Причина — type erasure и несовместимость ковариантных массивов с инвариантными дженериками.

// ❌ Все запрещены:
// T[] array = new T[10];
// List<String>[] array = new List<String>[10];

// ✅ Обходной путь:
@SuppressWarnings("unchecked")
T[] array = (T[]) java.lang.reflect.Array.newInstance(type, 10);
📌 Резюме для Middle+

Создание массивов дженериков запрещено. Обходные пути: Object[] с приведением, Array.newInstance через рефлексию, или коллекции (List<List<String>>). ArrayList внутри использует Object[], а не E[].

  • Предложить правильные альтернативы
  • Показать, что ArrayList использует Object[] внутри
Что такое bounded type parameters?

Краткий ответ: Bounded type parameters ограничивают тип-параметр верхней границей: <T extends Number>, <T extends Comparable<T>>. Позволяют вызывать методы граничного типа.

public class NumberBox<T extends Number> {
    public double sum(T a, T b) {
        return a.doubleValue() + b.doubleValue(); // ✅ метод Number!
    }
}

Multiple bounds

// Один класс (первый) + интерфейсы:
<T extends Number & Comparable<T>>
// Нельзя: <T extends Number & String> // Два класса!
📌 Резюме для Middle+

Bounded type parameters позволяют вызывать методы граничного типа. Синтаксис: один класс + интерфейсы через &. Отличие от wildcards: bounded type parameter позволяет и читать, и писать; ? extends — только читать; ? super — только писать.

🟢 Wildcards

В чём разница между <? extends T> и <? super T>?

Краткий ответ: <? extends T> — верхняя граница, для чтения. <? super T> — нижняя граница, для записи. Правило PECS.

Характеристика<? extends T><? super T>
ГраницаВерхняяНижняя
Чтение✅ Как T❌ Только как Object
Запись❌ Запрещена✅ Как T
PECSProducer ExtendsConsumer Super
📌 Резюме для Middle+

<? extends T> для чтения (производители), <? super T> для записи (потребители). Если нужны и чтение, и запись — <T> без wildcards.

🎯 Что показать на собеседовании
  • Почему нельзя писать в extends (неизвестен тип)
  • Почему нельзя читать из super (может быть Object)
  • Пример copy() с обоими wildcards
Что такое PECS (Producer Extends Consumer Super)?

Краткий ответ: PECS — правило выбора wildcard: Producer — ? extends T (чтение), Consumer — ? super T (запись).

public static <T> void copy(
    List<? extends T> source,  // PRODUCER — читаем
    List<? super T> target     // CONSUMER — пишем
) {
    for (T item : source) target.add(item);
}
📌 Резюме для Middle+

PECS — инструмент проектирования API. Показывает намерения: "этот метод только читает", "этот метод только пишет". Если и то, и другое — используйте <T>.

🔵 Ограничения и особенности

Можно ли использовать примитивные типы как параметры дженериков?

Краткий ответ: Нет. Дженерики работают только со ссылочными типами. Используйте классы-обёртки: Integer для int, Long для long, Double для double.

// ❌ List<int> list = new ArrayList<>();
// ✅ List<Integer> list = new ArrayList<>();
📌 Резюме для Middle+

Примитивы не могут быть параметрами дженериков из-за type erasure. Используйте обёртки. Для производительности — примитивные стримы или сторонние коллекции (Trove, Fastutil).

Что такое raw types и почему их следует избегать?

Краткий ответ: Raw type — использование дженерик-класса без указания типа-параметра (List вместо List<String>). Отключает проверку типов.

// ⚠️ Raw type
List rawList = new ArrayList();
rawList.add(42); // Компилятор не предупредит!

// ✅ Параметризованный тип
List<String> list = new ArrayList<>();
📌 Резюме для Middle+

Raw types отключают проверку типов, приводят к ClassCastException в рантайме. Существуют только для обратной совместимости. Используйте diamond-оператор или wildcard List<?>.

🎯 Что показать на собеседовании
  • Разницу между raw type и wildcard (raw опаснее)
  • Смешивание raw и параметризованных типов
  • Статические анализаторы (SonarQube, IntelliJ)
Что произойдёт при попытке создать экземпляр дженерик-типа через new T()?

Краткий ответ: Компилятор откажется компилировать. Ошибка: "Type parameter 'T' cannot be instantiated directly". Причина — type erasure.

// ❌ Ошибка!
public T createInstance() {
    return new T(); // Error!
}

// ✅ Правильно: Class<T> или Supplier<T>
public T create(Class<T> clazz) throws Exception {
    return clazz.getDeclaredConstructor().newInstance();
}
📌 Резюме для Middle+

new T() невозможен из-за type erasure. Правильные подходы: Class<T> (рефлексия), Supplier<T> (функциональный), статические методы с Class<T>.

  • Объяснить, почему Class<T> и Supplier<T> работают
  • Связанные ограничения (new T[], instanceof T)
В чём разница между List<?> и List<Object>?

Краткий ответ: List<Object> — конкретный тип для хранения любых объектов. List<?> — wildcard неизвестного типа для чтения.

ХарактеристикаList<Object>List<?>
Тип элементовКонкретный ObjectНеизвестный
Добавление✅ Любые❌ Только null
Чтение✅ Как Object✅ Как Object
ПрисвоениеТолько List<Object>Любой список
📌 Резюме для Middle+

List<Object> — для хранения, List<?> — для чтения. Ключевое: List<String> ≠ List<Object> (инвариантность), но List<String> = List<?> (wildcard принимает всё).

🟣 Наследование и методы

Можно ли перегружать методы, отличающиеся только дженерик-параметрами?

Краткий ответ: Нет. После type erasure сигнатуры совпадают, компилятор выдаёт ошибку "name clash".

// ❌ Ошибка!
public void process(List<String> strings) { }
public void process(List<Integer> integers) { }
// Оба становятся: process(List)
📌 Резюме для Middle+

Нельзя перегружать методы, отличающиеся только дженерик-параметрами. Для перегрузки: разные типы коллекций (List vs Set), разное количество параметров, разные имена методов.

  • Правильные способы перегрузки
  • Связь с bridge-методами
Что такое recursive type bound?

Краткий ответ: Recursive type bound — ограничение типа, которое ссылается на себя: <T extends Comparable<T>>.

public class SortedList<T extends Comparable<T>> {
    public T max() {
        // item.compareTo(max) — принимает T, а не Object!
    }
}
📌 Резюме для Middle+

Recursive type bound решает проблему типобезопасности: compareTo(T) вместо compareTo(Object). Используется в Comparable, Enum. Связан с паттерном CRTP.

🎯 Что показать на собеседовании
  • Пример с Comparable<T>
  • Проблему без recursive bound (небезопасный compareTo)
  • Паттерн self-referential generics
Как работают дженерики с наследованием (является ли List<String> подтипом List<Object>)?

Краткий ответ: Нет. List<String> НЕ является подтипом List<Object>. Дженерики инвариантны.

// ❌ Ошибка!
List<String> strings = new ArrayList<>();
// List<Object> objects = strings;

// ✅ Гибкость через wildcards
List<?> wildcard = new ArrayList<String>();
List<? extends Number> numbers = new ArrayList<Integer>();
📌 Резюме для Middle+

Дженерики инвариантны (в отличие от массивов). Причина — типобезопасность. Для гибкости — wildcards. Инвариантность — фича, а не ограничение.

  • Разницу между массивами (ковариантны) и дженериками (инвариантны)
  • Почему инвариантность защищает безопасность
  • Иерархию типов с wildcards
Что такое bridge methods и зачем они нужны?

Краткий ответ: Bridge methods — синтетические методы, добавляемые компилятором для сохранения полиморфизма после type erasure.

class Node<T> {
    public void setData(T data) { } // T → Object после стирания
}
class StringNode extends Node<String> {
    @Override public void setData(String data) { }
    // Bridge: public void setData(Object data) { setData((String) data); }
}
📌 Резюме для Middle+

Bridge-методы решают проблему: после стирания типов метод подкласса не переопределяет метод родителя. Bridge-метод приводит параметры и делегирует вызов. Синтетические — видны через рефлексию.

🎯 Что показать на собеседовании
  • Проблему type erasure (переопределение ломается)
  • Как bridge-метод решает (cast + делегирование)
  • Примеры генерации (наследование, интерфейсы, ковариантные возвраты)
Можно ли использовать несколько ограничений (bounds) для одного параметра типа?

Краткий ответ: Да. Синтаксис: <T extends ClassA & InterfaceB & InterfaceC>. Один класс (первый) + интерфейсы.

public class SmartNumber<T extends Number & Comparable<T>> {
    public boolean isBetween(T min, T max) {
        return value.compareTo(min) >= 0 && value.compareTo(max) <= 0;
    }
}
📌 Резюме для Middle+

Multiple bounds позволяют использовать методы из разных типов. Правила: один класс (первый), интерфейсы в любом количестве. Wildcards не поддерживают multiple bounds.

  • Почему класс должен быть первым
  • Практический пример SmartNumber
Как реализовать шаблон Singleton с помощью Record?

Краткий ответ: Record НЕ предназначен для Singleton. Его конструктор создаёт новый объект при каждом вызове, и его нельзя сделать private.

// ❌ Record не может быть Singleton:
public record Config(String url) { }
Config c1 = new Config("localhost");
Config c2 = new Config("localhost");
System.out.println(c1 == c2); // false!

Правильные альтернативы

// Enum (рекомендуется)
public enum Config { INSTANCE; }

// Классический Singleton
public class Config {
    private static final Config INSTANCE = new Config();
    private Config() { }
    public static Config getInstance() { return INSTANCE; }
}

// Комбинация: Record для данных + enum для Singleton
public record ConfigData(String url) { }
public enum Config { INSTANCE; private ConfigData data; }
📌 Резюме для Middle+

Record не может быть Singleton: публичный конструктор, создание новых объектов. Используйте enum или классический Singleton. Для иммутабельных данных — Record + enum.
