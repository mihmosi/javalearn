Часть 2: Структурные паттерны — Adapter, Decorator, Proxy, Composite, Facade, Bridge. Как соединять объекты между собой.

🟠 Структурные паттерны (Structural)

🔌 Adapter (Адаптер)

Краткий ответ: Adapter преобразует интерфейс одного класса в интерфейс, ожидаемый клиентом. Позволяет объектам с несовместимыми интерфейсами работать вместе.

Проблема

// Есть старый класс
class OldPrinter {
    void printOld() { System.out.println("Печать старым способом"); }
}

// Новый код ожидает интерфейс
interface Printer {
    void print();
}

Решение: Adapter

class PrinterAdapter implements Printer {
    private OldPrinter printer;

    public PrinterAdapter(OldPrinter printer) {
        this.printer = printer;
    }

    @Override
    public void print() {
        printer.printOld(); // делегирование старому классу
    }
}

// Использование
OldPrinter oldPrinter = new OldPrinter();
Printer printer = new PrinterAdapter(oldPrinter);
printer.print(); // Печать старым способом

Где используется в Java

  • InputStreamReader — адаптирует InputStream (byte) к Reader (char)
  • Arrays.asList() — адаптирует массив к интерфейсу List
  • Collections.enumeration() — адаптирует коллекцию к Enumeration
// Пример из JDK: InputStreamReader
InputStream byteStream = new FileInputStream("file.txt");
Reader charReader = new InputStreamReader(byteStream, StandardCharsets.UTF_8);
// InputStreamReader — адаптер между миром байтов и миром символов
🎀 Decorator (Декоратор)

Краткий ответ: Decorator позволяет динамически добавлять объекту новое поведение без изменения его класса. Главное преимущество перед наследованием — композиция вместо наследования, что делает код более гибким и соответствует OCP.

Проблема наследования (комбинаторный взрыв)

// Для Coffee с добавками через наследование пришлось бы создавать:
// MilkCoffee, SugarCoffee, MilkSugarCoffee, MilkCreamCoffee,
// SugarCreamCoffee, MilkSugarCreamCoffee... — комбинаторный взрыв!

Решение через Decorator

interface Coffee {
    double cost();
    String description();
}

class SimpleCoffee implements Coffee {
    public double cost() { return 2.0; }
    public String description() { return "Кофе"; }
}

abstract class CoffeeDecorator implements Coffee {
    protected Coffee decorated;
    CoffeeDecorator(Coffee c) { this.decorated = c; }
}

class MilkDecorator extends CoffeeDecorator {
    MilkDecorator(Coffee c) { super(c); }
    public double cost() { return decorated.cost() + 0.5; }
    public String description() { return decorated.description() + ", молоко"; }
}

class SugarDecorator extends CoffeeDecorator {
    SugarDecorator(Coffee c) { super(c); }
    public double cost() { return decorated.cost() + 0.3; }
    public String description() { return decorated.description() + ", сахар"; }
}

// Использование: любые комбинации без новых классов
Coffee coffee = new SimpleCoffee();
coffee = new MilkDecorator(coffee);
coffee = new SugarDecorator(coffee);
System.out.println(coffee.description() + " = " + coffee.cost());
// Кофе, молоко, сахар = 2.8

Основные преимущества

  1. Поведение можно менять во время выполнения — в отличие от наследования, где тип фиксирован.
  2. Нет комбинаторного взрыва классов — достаточно базовых декораторов.
  3. Соблюдение Open/Closed Principle — новый функционал через новый декоратор.
  4. Повторное использование — один декоратор можно применять к разным реализациям интерфейса.

Decorator в java.io

// Классический пример из JDK
InputStream in = new BufferedInputStream(          // добавляет буферизацию
                     new DataInputStream(          // добавляет чтение примитивов
                         new FileInputStream("data.bin"))); // читает файл
// Каждый класс расширяет поведение предыдущего, не изменяя его код

Другие примеры в JDK: BufferedReader, PrintWriter, Collections.synchronizedList(), Collections.unmodifiableList().

Decorator vs Наследование

НаследованиеDecorator
Поведение определяется при создании классаПоведение можно менять во время выполнения
Жёсткая связь с родителемГибкая композиция объектов
Быстро растёт количество классовНебольшое количество независимых декораторов
Изменения затрагивают иерархиюНовое поведение без изменения существующего кода

Недостатки

  • Увеличивается количество небольших классов
  • Длинная цепочка объектов усложняет отладку
🛡️ Proxy (Заместитель)

Краткий ответ: Proxy — структурный паттерн, предоставляющий объект-заместитель, контролирующий доступ к реальному объекту. Клиент работает не напрямую, а через заместителя.

Client → Proxy → RealService
// Proxy выполняет дополнительную логику: права, лог, кэш, lazy init

Типы Proxy

1. Virtual Proxy (Виртуальный Proxy)

Создаёт тяжёлый объект только когда он действительно понадобится (Lazy Initialization).

class ImageProxy implements Image {
    private RealImage realImage;
    private String filename;

    public void display() {
        if (realImage == null) {
            realImage = new RealImage(filename); // загрузка только при первом обращении
        }
        realImage.display();
    }
}

Для: больших изображений, тяжёлых объектов, дорогостоящих подключений, загрузки файлов.

2. Protection Proxy (Защитный Proxy)

Контролирует доступ к объекту. Proxy проверяет права перед вызовом.

class UserServiceProxy implements UserService {
    private UserService service;
    private User currentUser;

    public void deleteUser(Long id) {
        if (currentUser.isAdmin()) {
            service.deleteUser(id);
        } else {
            throw new AccessDeniedException("Admin access required");
        }
    }
}

Используется в Spring Security, Java Security Manager.

3. Remote Proxy (Удалённый Proxy)

Представляет объект на другом сервере. Клиент работает как с локальным. Proxy: сериализует запрос → отправляет по сети → получает ответ → десериализует.

Используется в: RMI, gRPC, REST-клиентах (OpenFeign в Spring Cloud).

4. Caching Proxy

class CachingUserService implements UserService {
    private UserService service;
    private Map<Long, User> cache = new ConcurrentHashMap<>();

    public User getUser(Long id) {
        return cache.computeIfAbsent(id, service::getUser);
    }
}

Redis, Caffeine, Spring Cache, Hibernate Second-Level Cache.

5. Logging (Smart) Proxy

Добавляет логирование, измерение времени, подсчёт вызовов, метрики, аудит.

class LoggingProxy implements Service {
    private Service service;
    public Result execute(Input in) {
        long start = System.nanoTime();
        Result result = service.execute(in);
        log.info("Method executed in {} ms", (System.nanoTime() - start) / 1_000_000);
        return result;
    }
}

Dynamic Proxy в Java

  • JDK Dynamic Proxy: через Proxy.newProxyInstance() и InvocationHandler, только для интерфейсов.
  • CGLIB Proxy: наследуется от класса, переопределяет методы. Нельзя проксировать final классы и методы.
// JDK Dynamic Proxy
InvocationHandler handler = (proxy, method, args) -> {
    System.out.println("Before " + method.getName());
    Object result = method.invoke(target, args);
    System.out.println("After " + method.getName());
    return result;
};
Service proxy = (Service) Proxy.newProxyInstance(
    Service.class.getClassLoader(),
    new Class[]{Service.class},
    handler
);

Где используется в Java

  • Spring AOP — прокси для аспектов
  • @Transactional — транзакции реализованы через Proxy
  • Spring Security — проверка прав
  • Hibernate — ленивые (LAZY) сущности через Proxy
  • Feign Client — удалённые вызовы

Proxy vs Decorator

ProxyDecorator
Контролирует доступ к объектуДобавляет новую функциональность
Часто создаётся фреймворкомОбычно собирается разработчиком

🌳 Composite (Компоновщик)

Краткий ответ: Composite группирует объекты в древовидные структуры для представления иерархий «часть-целое». Позволяет клиентам единообразно работать с отдельными объектами и их группами.

// Общий интерфейс для файлов и папок
interface FileSystemComponent {
    String getName();
    long getSize();
    void print(String indent);
}

// Лист — отдельный файл
class File implements FileSystemComponent {
    private String name;
    private long size;
    public long getSize() { return size; }
    public void print(String indent) { System.out.println(indent + "📄 " + name); }
}

// Композит — папка, содержащая другие компоненты
class Directory implements FileSystemComponent {
    private String name;
    private List<FileSystemComponent> children = new ArrayList<>();

    public void add(FileSystemComponent component) { children.add(component); }
    public long getSize() {
        return children.stream().mapToLong(FileSystemComponent::getSize).sum();
    }
    public void print(String indent) {
        System.out.println(indent + "📁 " + name);
        for (FileSystemComponent child : children) {
            child.print(indent + "  ");
        }
    }
}

Где используется в Java

  • Swing — контейнеры содержат другие компоненты (JPanel содержит JButton, JLabel)
  • java.awt.Component — базовый класс для всех GUI-элементов
  • Парсинг XML/JSON — элементы могут содержать вложенные элементы
🏰 Facade (Фасад)

Краткий ответ: Facade предоставляет унифицированный интерфейс к сложной подсистеме. Вместо множества вызовов клиент использует один простой метод.

// Сложная система: Engine, FuelSystem, Cooling, Battery, Starter
class Engine { void start() {} }
class FuelSystem { void pump() {} }
class Cooling { void activate() {} }
class Battery { void supply() {} }
class Starter { void engage() {} }

// Фасад
class CarFacade {
    private Engine engine = new Engine();
    private FuelSystem fuel = new FuelSystem();
    private Cooling cooling = new Cooling();
    private Battery battery = new Battery();
    private Starter starter = new Starter();

    public void start() {
        battery.supply();
        fuel.pump();
        cooling.activate();
        starter.engage();
        engine.start();
        System.out.println("Машина заведена!");
    }
}

// Клиент использует один простой вызов
CarFacade car = new CarFacade();
car.start();

Где используется в Java

  • JdbcTemplate (Spring) — фасад для работы с JDBC
  • HttpClient (Java 11+) — фасад для HTTP-запросов
  • SLF4J — фасад для различных систем логирования
🌉 Bridge (Мост)

Краткий ответ: Bridge отделяет абстракцию от её реализации, позволяя изменять их независимо. Предотвращает комбинаторный взрыв подклассов при наследовании по двум измерениям.

// Реализация — интерфейс устройства
interface Device {
    void turnOn();
    void setVolume(int percent);
}

class TV implements Device {
    public void turnOn() { System.out.println("Телевизор включён"); }
    public void setVolume(int p) { System.out.println("Громкость TV: " + p + "%"); }
}

class Radio implements Device {
    public void turnOn() { System.out.println("Радио включено"); }
    public void setVolume(int p) { System.out.println("Громкость Radio: " + p + "%"); }
}

// Абстракция — пульт управления
abstract class RemoteControl {
    protected Device device;
    RemoteControl(Device device) { this.device = device; }
    abstract void togglePower();
    abstract void volumeUp();
}

class BasicRemote extends RemoteControl {
    BasicRemote(Device device) { super(device); }
    void togglePower() { device.turnOn(); }
    void volumeUp() { device.setVolume(50); }
}

// Использование: комбинируем любые пульты с любыми устройствами
Device tv = new TV();
RemoteControl remote = new BasicRemote(tv);
remote.togglePower(); // Телевизор включён

Где используется в Java

  • JDBC — DriverManager (абстракция) и конкретные драйверы (реализация)
  • SLF4J — API логирования (абстракция) и Logback/Log4j (реализация)
  • java.awt — Component (абстракция) и нативные реализации для разных ОС
