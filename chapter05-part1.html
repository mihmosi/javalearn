🔷 Устройство HashMap

Как устроена HashMap внутри?

Краткий ответ: HashMap — это массив корзин (buckets), каждая из которых представляет собой связный список или красно-чёрное дерево. Ключ-значение хранится в виде объекта Node. Индекс корзины вычисляется как hash(key) & (capacity - 1). При коллизиях элементы добавляются в список/дерево. При достижении порога загрузки массив увеличивается вдвое и все элементы перехешируются.

1. Структура хранения

До Java 8 HashMap состоял из массива Entry<K,V>[] table (корзины), каждая корзина — связный список Entry (односвязный). С Java 8 структура усложнилась: массив Node<K,V>[] table, корзина может быть null (пустая), односвязным списком Node, или красно-чёрным деревом TreeNode.

class Node {
    final int hash;     // хеш ключа
    final K key;
    V value;
    Node next;     // следующий в цепочке
}

2. Как вычисляется индекс корзины

int hash = key.hashCode();
hash = hash ^ (hash >>> 16);  // "xor shift" для лучшего распределения
int index = hash & (table.length - 1);

Почему hash ^ (hash >>> 16)? Старшие 16 бит перемешиваются с младшими, чтобы улучшить распределение. Почему & (table.length - 1)? Поскольку размер таблицы всегда степень двойки (16, 32, 64...), вычитание единицы даёт битовую маску (15 = 1111, 31 = 11111), а побитовое & работает как быстрое деление по модулю.

3. Разрешение коллизий

Когда два разных ключа попадают в одну корзину, они хранятся в цепочке. С Java 8: ≤ 8 элементов — связный список; > 8 (TREEIFY_THRESHOLD) — красно-чёрное дерево; < 6 — обратно в список (UNTREEIFY_THRESHOLD). Порог 8 выбран на основе распределения Пуассона (вероятность ~0.00000006).

4. Красно-чёрное дерево и сравнение ключей

Порядок поиска компаратора: 1) Comparable.compareTo(); 2) System.identityHashCode(); 3) tieBreakOrder() (сравнение имён классов).

5. Ключевые константы

КонстантаЗначениеОписание
DEFAULT_INITIAL_CAPACITY16Начальный размер массива
DEFAULT_LOAD_FACTOR0.75Порог загрузки
TREEIFY_THRESHOLD8Порог для деревофикации
UNTREEIFY_THRESHOLD6Порог для обратно в список
MIN_TREEIFY_CAPACITY64Минимальный размер для деревофикации

6. Расширение массива (resize)

Когда size > capacity * loadFactor (16 * 0.75 = 12), массив увеличивается вдвое. Поскольку размер всегда степень двойки, элемент либо остаётся в той же корзине, либо перемещается в oldIndex + oldCapacity.

7. Требования к ключам

  • hashCode() — должен быть стабильным
  • equals() — согласован с hashCode()
  • Если ключ изменяется после вставки — он "теряется"

8. Производительность

removeO(1)O(log n)

Что такое bucket (корзина) в HashMap?

Краткий ответ: Bucket (корзина) — это ячейка внутреннего массива HashMap, которая хранит один или несколько элементов с одинаковым индексом. Технически это элемент массива Node<K,V>[] table.

1. Как выглядит корзина в памяти

HashMap
├── table[0]  → null                           (пустая корзина)
├── table[1]  → Node("key1") → Node("key2")     (связный список)
├── table[2]  → TreeNode("key3")                (красно-чёрное дерево)
│               ├── left: TreeNode
│               └── right: TreeNode

2. Как определяется корзина

int hash = key.hashCode();
hash = hash ^ (hash >>> 16);
int bucketIndex = hash & (table.length - 1);
// Пример: hash=18 → 18 & 15 = 2 (корзина №2)

3. Что хранится в корзине

До Java 8 — голова связного списка Entry. С Java 8: null (пусто), Node (список ≤ 8), TreeNode (дерево > 8).

static class Node {
    final int hash; final K key; V value;
    Node next;
}

4. Условия деревофикации

≥ 8 элементов в корзине И размер таблицы ≥ 64. Если таблица < 64 — вместо деревофикации resize().

Как HashMap определяет, в какой bucket положить элемент?

Краткий ответ: Индекс корзины вычисляется в два шага: XOR-шифтинг хеша, затем побитовое И с маской (capacity - 1). Формула: index = (key.hashCode() ^ (key.hashCode() >>> 16)) & (table.length - 1).

Шаг 1: Получение хеша ключа

int h = key.hashCode(); // например, для "apple" = 93029210

Шаг 2: Перемешивание битов (XOR-шифтинг)

int hash = h ^ (h >>> 16);
// h        = 1110 1011 0101 0011 1100 0001 0010 1010
// h >>> 16 = 0000 0000 0000 0000 1110 1011 0101 0011
// h^h>>>16 = 1110 1011 0101 0011 0010 1010 0111 1001

Старшие биты "впечатываются" в младшие, улучшая распределение при малом размере таблицы.

Шаг 3: Вычисление индекса через битовую маску

int index = hash & (table.length - 1);
// length=16 → 15=0b1111, length=32 → 31=0b11111

Побитовое И с маской — быстрый аналог hash % length (1 такт вместо 10-30).

Полный пример

// Ключ "apple"
int h = "apple".hashCode();         // 93029210
int hash = h ^ (h >>> 16);          // 93030397
int index = hash & (16 - 1);        // 93030397 & 15 = 13 → корзина №13

Особый случай: null-ключ

if (key == null) return 0; // null всегда в корзине №0
Что такое коллизия в HashMap?

Краткий ответ: Коллизия — это ситуация, когда два разных ключа получают одинаковый индекс корзины. Элементы с одинаковым индексом объединяются в цепочку — связный список или красно-чёрное дерево.

1. Почему возникают коллизии

// capacity = 16
"apple"  → hashCode() = 93029210  → hash & 15 = 10
"orange" → hashCode() = -1008851410 → hash & 15 = 10 // коллизия!

Причины: разные hashCode могут дать одинаковый индекс; одинаковые hashCode у разных объектов (закон больших чисел для 32-битного int).

2. Два вида коллизий

Вид 1: Разные hashCode → одинаковый индекс (самая частая). Вид 2: Одинаковый hashCode — "Aa" и "BB" → 2112.

3. Как HashMap различает ключи при коллизии

while (current != null) {
    if (current.hash == hash &&        // Сначала сравнение хешей (быстро, int)
        key.equals(current.key)) {     // Потом equals (только при совпадении хеша)
        return current;
    }
    current = current.next;
}

4. Влияние коллизий на производительность

Количество коллизийПроизводительностьСтруктура
0O(1)Один узел
1-8Близко к O(1)Связный список
> 8O(log n)Красно-чёрное дерево
Как HashMap обрабатывает коллизии?

Краткий ответ: HashMap обрабатывает коллизии методом цепочек (separate chaining). До Java 8 — только связный список. С Java 8 — список до 8 элементов, затем красно-чёрное дерево для защиты от деградации до O(n).

1. Метод цепочек (Separate Chaining)

static class Node {
    final int hash; final K key; V value;
    Node next; // следующий узел в цепочке
}

2. Пошаговый алгоритм put() при коллизии

// Шаг 1: Корзина пуста — просто кладём
if (table[index] == null) { table[index] = new Node(...); return; }
// Шаг 2: Обходим цепочку
Node current = table[index];
while (current != null) {
    if (current.hash == hash && key.equals(current.key)) {
        current.value = value; return; // замена
    }
    if (current.next == null) { current.next = new Node(...); break; }
    current = current.next;
}

3. Поиск в цепочке при get()

while (current != null) {
    if (current.hash == hash && key.equals(current.key)) return current.value;
    current = current.next;
}
return null;

4. Деревофикация (JDK 8+)

if (binCount >= TREEIFY_THRESHOLD - 1) {  // ≥ 8 элементов
    if (table.length < MIN_TREEIFY_CAPACITY) resize(); // < 64
    else treeifyBin(tab, hash); // ≥ 64 → дерево
}

5. Сравнение ключей в дереве

// 1. Comparable.compareTo()
// 2. System.identityHashCode()
// 3. tieBreakOrder (сравнение имён классов)
Что происходит при достижении 8 элементов в одном bucket?

Краткий ответ: Если размер таблицы < 64 → resize() (расширение). Если ≥ 64 → treeifyBin() (связный список → красно-чёрное дерево).

Пошаговый разбор

// Константы
static final int TREEIFY_THRESHOLD = 8;
static final int MIN_TREEIFY_CAPACITY = 64;

// Логика
if (binCount >= TREEIFY_THRESHOLD - 1) {
    if (table.length < MIN_TREEIFY_CAPACITY) resize();
    else treeifyBin(tab, hash);
}

Два возможных исхода

capacity < 64 → resize()
    ├── массив увеличивается вдвое
    ├── все элементы перехешируются по новым корзинам
    └── цепочка естественно разбивается

capacity ≥ 64 → treeifyBin()
    ├── Node заменяются на TreeNode
    ├── связный список → красно-чёрное дерево
    └── поиск: O(n) → O(log n)

Почему порог именно 8?

Распределение Пуассона: вероятность 8 элементов в корзине при хорошем hashCode ≈ 0.00000006 — настолько редко, что это сигнал проблемы (атака или плохой hashCode).

Обратный процесс — Untreeify

// При ≤ 6 элементах дерево → обратно в список
if (root == null || root.right == null || root.left == null || root.left.left == null) {
    tab[index] = first.untreeify(map);
}

🟠 Контракт equals() и hashCode()

Что такое контракт equals() и hashCode()?

Краткий ответ: Набор правил из Javadoc класса Object. Главное правило: если два объекта равны по equals(), их hashCode() обязан быть одинаковым. Обратное не требуется. Нарушение контракта приводит к некорректной работе HashSet, HashMap и других хеш-структур.

1. Контракт equals()

ПравилоОписание
Рефлексивностьx.equals(x) всегда true
Симметричностьx.equals(y) == y.equals(x)
Транзитивностьесли x.equals(y) и y.equals(z), то x.equals(z)
Консистентностьповторные вызовы возвращают одно и то же, пока объекты не изменились
null-безопасностьx.equals(null) всегда false

2. Контракт hashCode()

ПравилоОписание
КонсистентностьПовторные вызовы — одно значение, пока поля не изменились
Связь с equalsЕсли a.equals(b) == true, то a.hashCode() == b.hashCode() ОБЯЗАТЕЛЬНО
Неравные объектыЕсли a.equals(b) == false, hashCode МОГУТ совпадать (коллизия) или различаться

3. Связь между equals и hashCode

hashCode разные → equals гарантированно false (разные корзины)
hashCode одинаковые → equals может быть true или false (коллизия)

4. Правильный шаблон реализации

public class User {
    private final Long id; private final String name; private final String email;

    @Override public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        User user = (User) o;
        return Objects.equals(id, user.id) &&
               Objects.equals(name, user.name) &&
               Objects.equals(email, user.email);
    }

    @Override public int hashCode() {
        return Objects.hash(id, name, email); // ТЕ ЖЕ ПОЛЯ
    }
}

5. Почему поля должны быть неизменяемыми

// Опасный код: изменяемый ключ в HashMap
MutableKey key = new MutableKey("Alice");
map.put(key, "value");
key.setName("Bob"); // КЛЮЧ ИЗМЕНИЛСЯ!
map.get(key); // null — "потерялся"!
Если два объекта равны по equals(), что можно сказать об их hashCode()?

Краткий ответ: Их hashCode() обязан быть одинаковым. Это жёсткое требование контракта. Нарушение → объект "теряется" в HashMap.

Правило контракта

if (a.equals(b) == true) {
    // ГАРАНТИРОВАНО: a.hashCode() == b.hashCode()
}

Почему это критично для HashMap

User u1 = new User(1, "Alice"); // hashCode = 12345
User u2 = new User(1, "Alice"); // hashCode = 67890 — НАРУШЕНИЕ!
map.put(u1, "value1");
map.get(u2); // null! Поиск в другой корзине

Визуализация

✅ ПРАВИЛЬНО: equals=true, hashCode одинаковый
u1(Alice) → hashCode=12345 → корзина 9
u2(Alice) → hashCode=12345 → корзина 9 → equals=true → НАЙДЕН

❌ НАРУШЕНИЕ: equals=true, hashCode разный
u1(Alice) → hashCode=12345 → корзина 9
u2(Alice) → hashCode=67890 → корзина 10 → ПУСТО → НЕ НАЙДЕН
Если два объекта имеют одинаковый hashCode(), обязательно ли они равны по equals()?

Краткий ответ: Нет, не обязательно. Это коллизия — нормальная и допустимая ситуация, которую HashMap корректно обрабатывает через цепочки.

Правило контракта

if (a.hashCode() == b.hashCode()) {
    // a.equals(b) МОЖЕТ быть true (тот же ключ)
    // a.equals(b) МОЖЕТ быть false (коллизия)
}

Пример неизбежной коллизии

"Aa".hashCode();   // 2112
"BB".hashCode();   // 2112 — коллизия!
"Aa".equals("BB"); // false — разные строки

Как HashMap обрабатывает одинаковый hashCode при разных equals

map.put("Aa", "value1"); // hashCode=2112 → корзина X
map.put("BB", "value2"); // hashCode=2112 → та же корзина
// table[X] → Node("Aa") → Node("BB")
map.get("Aa"); // hashCode→корзина X→equals("Aa","Aa")=true→"value1"
map.get("BB"); // hashCode→корзина X→equals("BB","Aa")=false→equals("BB","BB")=true→"value2"

Все четыре комбинации

hashCodeequalsСитуация
ОдинаковыйtrueОдин и тот же ключ
ОдинаковыйfalseКоллизия (норма)
РазныйtrueНарушение контракта
РазныйfalseРазные объекты (норма)
Что произойдёт, если переопределить equals() но не переопределить hashCode()?

Краткий ответ: Нарушится контракт hashCode(). Объекты, равные по equals(), будут иметь разные хеш-коды (унаследованные от Object). HashMap/HashSet сломаются: get() → null, contains() → false.

Демонстрация проблемы

class User {
    private String name;
    @Override public boolean equals(Object o) {
        if (!(o instanceof User)) return false;
        return Objects.equals(name, ((User) o).name);
    }
    // hashCode НЕ переопределён → Object.hashCode()
}
User u1 = new User("Alice"); User u2 = new User("Alice");
System.out.println(u1.equals(u2)); // true
System.out.println(u1.hashCode() == u2.hashCode()); // false — НАРУШЕНИЕ!

Map map = new HashMap<>();
map.put(u1, "value");
map.get(u2); // null — РАВНЫЙ объект НЕ НАХОДИТ!

Механика отказа

put(u1): hashCode(u1)=12345 → index=9 → table[9]=u1
get(u2): hashCode(u2)=67890 → index=10 → table[10]=null → return null

HashMap сначала определяет корзину по hashCode, и только внутри корзины сравнивает по equals. Разные hashCode → разные корзины → equals никогда не будет вызван.

Последствия для разных коллекций

КоллекцияПоведение
HashMapget() → null, containsKey() → false
HashSetcontains() → false, можно добавить "дубликат"
ArrayList✅ Работает (indexOf, contains только equals)
TreeSet/TreeMap✅ Работает (compareTo, не hashCode)
Что произойдёт, если переопределить hashCode() но не переопределить equals()?

Краткий ответ: Объекты будут попадать в одну корзину (hashCode совпадает), но equals() сравнивает ссылки (Object.equals). Логически одинаковые объекты считаются разными ключами.

Демонстрация проблемы

class User {
    private String name;
    @Override public int hashCode() { return Objects.hash(name); }
    // equals НЕ переопределён → Object.equals() сравнивает ССЫЛКИ
}
User u1 = new User("Alice"); User u2 = new User("Alice");
System.out.println(u1.hashCode() == u2.hashCode()); // true
System.out.println(u1.equals(u2)); // false — разные ссылки!

Map map = new HashMap<>();
map.put(u1, "value1");
map.put(u2, "value2"); // ДОБАВЛЕН как ОТДЕЛЬНЫЙ ключ!
System.out.println(map.size()); // 2 — оба в одной корзине, но разные ключи

Механика работы HashMap

put(u1): hashCode=12345 → корзина 9 → table[9]=u1
put(u2): hashCode=12345 → та же корзина 9
    Обход: u2.equals(u1)=false (ссылки!) → идём дальше
    Конец цепочки → ДОБАВЛЯЕМ u2 как новый узел
    table[9] = u1 → "value1" → u2 → "value2"
