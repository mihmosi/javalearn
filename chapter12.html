🔷 Основы Records

Что такое Record в Java и с какой версии они доступны?

Краткий ответ: Record — это специальный вид класса в Java, предназначенный для хранения неизменяемых данных. Доступен с Java 14 (Preview), а как стабильная фича — с Java 16.

Развёрнутое объяснение

Records решают проблему многословности при создании простых классов-носителей данных (DTO, Value Objects). Раньше для создания иммутабельного объекта с полями x и y приходилось писать конструктор, геттеры, equals(), hashCode(), toString() — около 50 строк кода. Record делает то же самое в одну строку:

public record Point(int x, int y) {}

Компилятор автоматически генерирует: приватные финальные поля, канонический конструктор, геттеры без префикса get (просто x() и y()), equals(), hashCode(), toString().

Базовое объявление и использование

public record Point(int x, int y) {}

Point p = new Point(10, 20);
int x = p.x();       // геттер без префикса get
int y = p.y();
System.out.println(p); // Point[x=10, y=20]

Ключевые особенности

  • Все поля неизменяемые (private final)
  • Record неявно финальный — нельзя наследоваться от record
  • Record не может наследовать другие классы (неявно extends java.lang.Record)
  • Можно переопределить конструктор или геттеры
  • Поддерживает компактный конструктор для валидации
  • Можно добавлять статические поля, методы и нестатические методы
📌 Резюме для Middle+

Record — это не просто синтаксический сахар, а семантический сдвиг: класс определяется своими данными, а не поведением. Появились как Preview в Java 14, стабильны с Java 16. Record заменяет ~50 строк boilerplate-кода одной строкой. Компилятор автоматически генерирует конструктор, геттеры, equals, hashCode и toString на основе компонентов. Record неявно final и неявно extends java.lang.Record.

В чём основные отличия Record от обычного класса?

Краткий ответ: Record — это иммутабельный, финальный класс, где состояние задаётся только через канонический конструктор, а идентичность определяется исключительно данными. Обычный класс таких ограничений не имеет.

1. Иммутабельность

// Record — все поля final
public record Point(int x, int y) {}

// Обычный класс — поля могут быть не final, есть сеттеры
public class MutablePoint {
    private int x;
    public void setX(int x) { this.x = x; }
}

2. Наследование

// Record — final, нельзя наследовать
public record Circle(double radius) implements Shape {}

// Ошибка компиляции — record не может наследовать класс
// public record MyCircle(double radius) extends Circle {} // ❌

// Ошибка компиляции — нельзя унаследоваться от record
// public class MyPoint extends Point {} // ❌

3. Идентичность (equals/hashCode)

// Record — автоматический структурный equals
Point p1 = new Point(5, 5);
Point p2 = new Point(5, 5);
System.out.println(p1.equals(p2)); // true без написания equals

// Обычный класс — без переопределения equals сравниваются ссылки
System.out.println(op1.equals(op2)); // false

4. Геттеры без префикса get

Point p = new Point(10, 20);
p.x(); // record style — без get

// Обычный класс
class PointClass {
    public int getX() { return x; } // классический стиль
}

5. Автоматическая генерация

Record генерирует канонический конструктор, toString(), equals(), hashCode() автоматически. Обычный класс — нужно писать вручную.

6. Поля экземпляра

// Record — нельзя добавить доп. поля экземпляра
public record Person(String name) {
    // private String nickname; // ❌ Ошибка компиляции
    private static int counter = 0; // ✅ Статическое — можно
}

// Обычный класс — можно что угодно
public class PersonClass {
    private String name;
    private String nickname; // ✅ Можно
}

Можно ли наследоваться от Record или наследовать Record от другого класса?

Краткий ответ: Нет, наследоваться от Record нельзя (он неявно final), и Record не может наследовать другой класс, потому что уже неявно наследует java.lang.Record. Единственное, что можно — реализовывать интерфейсы.

1. Record не может наследовать другой класс

// ✅ Можно — неявно extends java.lang.Record
public record Point(int x, int y) {}

// ❌ Нельзя — уже есть неявный extends Record
public record Point3D(int x, int y, int z) extends Point {} // Ошибка компиляции

2. От Record нельзя наследоваться

public record Point(int x, int y) {}

// ❌ Ошибка компиляции — Point неявно final
class ExtendedPoint extends Point { } // cannot inherit from final Point

3. Единственный способ расширения — интерфейсы

public interface Shape {
    double area();
    String description();
}

public record Circle(double radius) implements Shape {
    public double area() { return Math.PI * radius * radius; }
    public String description() { return "Круг с радиусом " + radius; }
}

public record Rectangle(double width, double height) implements Shape {
    public double area() { return width * height; }
    public String description() { return "Прямоугольник " + width + "x" + height; }
}

4. Sealed-иерархии (Java 17+)

public sealed interface Result permits Success, Failure, Loading {
    String message();
}

public record Success(String message, Object data) implements Result {}
public record Failure(String message, String errorCode) implements Result {}
public record Loading(String message, int progressPercent) implements Result {}
📌 Резюме для Middle+

Наследование для Record полностью запрещено. extends для record — нельзя (уже extends java.lang.Record). Наследоваться от record — нельзя (неявно final). Реализация интерфейсов — разрешена и является рекомендуемым подходом для полиморфизма. Sealed-интерфейсы идеально сочетаются с records для создания алгебраических типов данных (ADT).

Можно ли добавлять дополнительные методы в Record?

Краткий ответ: Да, можно добавлять любые методы — статические, нестатические и даже переопределять стандартные. Единственное ограничение — нельзя добавлять нестатические поля экземпляра.

public record Rectangle(double width, double height) {
    public double area() { return width * height; }
    public double perimeter() { return 2 * (width + height); }
    public boolean isSquare() { return width == height; }
    public Rectangle scale(double factor) {
        return new Rectangle(width * factor, height * factor);
    }
}

Какие методы автоматически генерируются для Record?

Краткий ответ: Автоматически генерируются: канонический конструктор, геттеры для всех компонентов, equals(), hashCode() и toString().

🟠 Конструкторы Record

Можно ли переопределить конструктор в Record?

Краткий ответ: Да, конструктор в Record можно переопределить. Есть два способа: канонический (с полным списком параметров) и компактный (без параметров).

// Канонический конструктор
public record Point(int x, int y) {
    public Point(int x, int y) {
        if (x < 0 || y < 0) throw new IllegalArgumentException();
        this.x = x;
        this.y = y;
    }
}

// Компактный конструктор
public record Point(int x, int y) {
    public Point {
        if (x < 0 || y < 0) throw new IllegalArgumentException();
        // this.x = x; this.y = y; — компилятор добавит автоматически
    }
}

// Перегрузка — дополнительные конструкторы
public record Point(int x, int y) {
    public Point {
        if (x < 0 || y < 0) throw new IllegalArgumentException();
    }
    public Point() { this(0, 0); }
    public Point(int n) { this(n, n); }
}

Что такое компактный конструктор (compact constructor) в Record?

Краткий ответ: Компактный конструктор — особый синтаксис в Record без списка параметров и без явного присвоения полей. Вы пишете только логику (валидацию, нормализацию), а компилятор автоматически добавляет присвоение полей в конце.

public record Point(int x, int y) {
    public Point {
        if (x < 0 || y < 0) throw new IllegalArgumentException();
        // this.x = x; this.y = y; — автоматически
    }
}

Что НЕЛЬЗЯ делать

public Point {
    this.x = x; // ❌ Нельзя явно присваивать поля
    this.toString(); // ❌ Нельзя использовать this
    int temp = 0; // ❌ Нельзя объявлять локальные переменные
    x = Math.abs(x); // ✅ Можно изменять параметры
}

Примеры использования

// Валидация
public record Age(int value) {

// Нормализация
public record Email(String value) {

Компилятор сам добавляет this.field = param. Можно изменять параметры — они будут сохранены в поля. Предпочтительный способ валидации в Record.

🟢 Статические члены и поля

Можно ли объявлять статические поля и методы в Record?

Краткий ответ: Да, можно. Record поддерживает статические поля (обязательно с инициализацией), статические константы, статические методы и статические вложенные классы. Нельзя объявлять нестатические поля экземпляра.

public record Circle(double radius) {
    public static final double PI = 3.14159;
    private static final double MIN_RADIUS = 0.0;
    
    public static Circle fromDiameter(double diameter) {
        return new Circle(diameter / 2);
    }
}

Являются ли поля Record финальными?

Краткий ответ: Да. Все поля Record неявно final. Компилятор автоматически делает каждое поле компонента private final. Нельзя изменить значение поля после создания объекта.

public record Point(int x, int y) {
    // Компилятор генерирует:
    // private final int x;
    // private final int y;
}

Point p = new Point(5, 10);
// p.x = 7;  // Ошибка! Нет сеттеров, поля private final

Что делать, если нужна "изменяемость"

public record Point(int x, int y) {
    public Point withX(int newX) { return new Point(newX, this.y); }
    public Point withY(int newY) { return new Point(this.x, newY); }
}

Point p2 = p.withX(7); // новый объект, оригинал не изменён

Проблема с mutable-полями

// ⚠️ Финальная ссылка не делает объект иммутабельным
public record User(String name, List roles) { }
User user = new User("Alice", new ArrayList<>());
user.roles().add("ADMIN"); // ← объект изменился!

// ✅ Решение — защитное копирование
public record User(String name, List roles) {
    public User { roles = List.copyOf(roles); }
}
📌 Резюме для Middle+

Все поля Record неявно final (private final). Компилятор автоматически добавляет final к каждому компоненту. Это обеспечивает иммутабельность — ключевое свойство Record. Важный нюанс: финальность поля не гарантирует иммутабельности всего объекта, если тип поля — mutable (ArrayList, Date, массив) — нужно защитное копирование.

Что такое защитное копирование?

Краткий ответ: Защитное копирование (defensive copying) — создание копии объекта при получении или возврате ссылки на него, чтобы внешний код не мог изменить внутреннее состояние. В Record это критично, потому что финальность поля защищает только ссылку, но не сам объект.

// Проблема: финальная ссылка ≠ неизменяемый объект
public record User(String name, List roles) { }
user.roles().add("ADMIN"); // ← Record изменился!

// Решение: защитное копирование в конструкторе
public record User(String name, List roles) {
    public User {
        roles = List.copyOf(roles); // КОПИЯ, не оригинал
    }
}

List, Set, Map✅ НужноМогут быть mutable

📌 Резюме для Middle+

Защитное копирование — обязательная практика при работе с Record, содержащими mutable-типы. Правильный подход: создавать копию в конструкторе (List.copyOf(), clone(), new Date(date.getTime())) и возвращать копию или неизменяемое представление в аксессоре. Это гарантирует, что Record действительно иммутабельный.

  • Проблему: финальная ссылка ≠ иммутабельность
  • Решение: List.copyOf(), clone(), new Date(date.getTime())
  • Двойную защиту: в конструкторе и в аксессоре

🔵 Record в коллекциях

Можно ли использовать Record как ключ в HashMap?

Краткий ответ: Да, Record — идеальный ключ для HashMap. Компилятор автоматически генерирует корректные equals(), hashCode() и toString() на основе всех полей. Record иммутабельны, что является ключевым требованием для ключей HashMap.

public record Point(int x, int y) { }

Map map = new HashMap<>();
map.put(new Point(1, 2), "A");
map.put(new Point(1, 2), "B"); // заменяет "A" — equals и hashCode совпадают
map.get(new Point(1, 2)); // "B" — найден!

Составной ключ

public record OrderKey(Long userId, Long orderId) { }
Map orders = new HashMap<>();
orders.put(new OrderKey(1L, 100L), new Order());
orders.get(new OrderKey(1L, 100L)); // найден

Проблема: mutable-поля

// ⚠️ Опасно: hashCode изменится, ключ "потеряется"
public record UserKey(List roles) { }
key.roles().add("USER"); // hashCode изменился!
map.get(key); // null — КЛЮЧ ПОТЕРЯН!

// ✅ Решение
public record UserKey(List roles) {
    public UserKey { roles = List.copyOf(roles); }
}
📌 Резюме для Middle+

Record — идеальный ключ для HashMap. Три ключевых свойства: иммутабельность (final поля), корректный equals() (сравнивает все поля), корректный hashCode() (на основе всех полей). Record заменяет ~50 строк кода традиционного класса одной строкой. Единственная опасность — mutable-поля: нужна защитная копия.
