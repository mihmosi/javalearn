🟢 Поведенческие паттерны (Behavioral)

🎯 Strategy (Стратегия)

Краткий ответ: Strategy — поведенческий паттерн, который инкапсулирует разные алгоритмы в отдельные классы и позволяет выбирать нужный во время выполнения без изменения кода клиента.

Когда применять

  • существует несколько алгоритмов, решающих одну задачу;
  • алгоритмы должны быть взаимозаменяемыми;
  • необходимо избежать большого количества if-else или switch;
  • требуется соблюдать принцип Open/Closed (OCP);
  • поведение объекта должно изменяться во время выполнения.

Структура

Context ──→ Strategy (интерфейс)
               ▲
               │
          ConcreteStrategyA
          ConcreteStrategyB

Пример: способы оплаты

interface PaymentStrategy {
    void pay(double amount);
}

class CardPayment implements PaymentStrategy {
    public void pay(double amount) {
        System.out.println("Оплата картой: " + amount);
    }
}

class PayPalPayment implements PaymentStrategy {
    public void pay(double amount) {
        System.out.println("Оплата через PayPal: " + amount);
    }
}

class CryptoPayment implements PaymentStrategy {
    public void pay(double amount) {
        System.out.println("Оплата криптовалютой: " + amount);
    }
}

class PaymentService {
    private PaymentStrategy strategy;

    public PaymentService(PaymentStrategy strategy) { this.strategy = strategy; }
    public void setStrategy(PaymentStrategy strategy) { this.strategy = strategy; }

    public void checkout(double amount) { strategy.pay(amount); }
}

// Использование
PaymentService service = new PaymentService(new CardPayment());
service.checkout(1000);
service.setStrategy(new PayPalPayment()); // меняем стратегию
service.checkout(500);

Где используется в Java

  • Comparator — разные стратегии сравнения объектов
  • Executor / ExecutorService — разные стратегии выполнения задач
  • Collections.sort(list, comparator) — стратегия сортировки
  • HttpClient.Redirect — стратегии обработки редиректов

Преимущества и недостатки

Плюсы: избавляет от if-else, соответствует OCP и SRP, алгоритмы легко тестировать, можно менять поведение во время выполнения.

Минусы: увеличивается количество классов, клиент должен знать какую стратегию выбрать.

Отличие от State

Strategy — клиент осознанно выбирает алгоритм. State — объект сам меняет поведение при изменении состояния. В Strategy меняется способ выполнения задачи, в State — поведение объекта.

👀 Observer (Наблюдатель)

Краткий ответ: Observer — поведенческий паттерн, реализующий связь «один ко многим»: объект-издатель хранит список подписчиков и уведомляет их при изменении своего состояния.

Типичная реализация

interface Observer {
    void update(String event);
}

class EventBus {
    private final List<Observer> observers = new ArrayList<>();

    public void subscribe(Observer observer) { observers.add(observer); }
    public void unsubscribe(Observer observer) { observers.remove(observer); }

    public void publish(String event) {
        for (Observer observer : observers) {
            observer.update(event);
        }
    }
}

// Использование
EventBus bus = new EventBus();
bus.subscribe(event -> System.out.println("Email: " + event));
bus.subscribe(event -> System.out.println("SMS: " + event));
bus.publish("Order created");
// Email: Order created
// SMS: Order created

Где используется в Java

  • PropertyChangeListener / PropertyChangeSupport — отслеживание изменений свойств
  • Swing — button.addActionListener(...), вся модель обработки событий
  • JavaFX — ObservableValue, ChangeListener
  • Flow API (Java 9) — Flow.Publisher, Flow.Subscriber с поддержкой backpressure
  • Spring Events — @EventListener, ApplicationEventPublisher

Почему Observable устарел?

java.util.Observable и java.util.Observer признаны неудачными: Observable — класс, а не интерфейс (нельзя наследоваться от другого класса), плохая расширяемость, неудобная работа с потоками, отсутствие backpressure. Начиная с Java 9 они deprecated.

Потокобезопасность

В многопоточном приложении использовать CopyOnWriteArrayList или ConcurrentHashMap вместо обычного ArrayList. Если подписчики подписываются/отписываются одновременно с рассылкой — нужны потокобезопасные коллекции.

Observer vs Publisher-Subscriber

Observer — издатель знает своих подписчиков и хранит их список. Publisher-Subscriber — между ними брокер сообщений (Kafka, RabbitMQ), издатель и подписчики не знают друг о друге.

Применение на реальных проектах

  • публикация доменных событий (OrderCreatedEvent)
  • уведомления по email, SMS, push
  • обработка заказов, логирование, аудит
  • обновление кэша, реактивные системы (Reactor, RxJava)
🎮 Command (Команда)

Краткий ответ: Command — поведенческий паттерн, представляющий действие как объект. Позволяет хранить команды, ставить их в очередь, логировать и поддерживать отмену операций.

Структура

interface Command {
    void execute();
    void undo(); // опционально
}

// Конкретная команда
class SaveCommand implements Command {
    private Document document;

    public SaveCommand(Document document) { this.document = document; }

    public void execute() {
        document.save();
        System.out.println("Документ сохранён");
    }

    public void undo() {
        document.revert();
        System.out.println("Сохранение отменено");
    }
}

// Invoker — вызывает команду
class Button {
    private Command command;

    public void setCommand(Command command) { this.command = command; }
    public void click() { command.execute(); }
}

// Использование
Document doc = new Document();
Command save = new SaveCommand(doc);
Button saveButton = new Button();
saveButton.setCommand(save);
saveButton.click(); // Документ сохранён

Где используется в Java

  • Runnable — команда для выполнения в потоке
  • Callable — команда, возвращающая результат
  • Swing Action — команда для GUI-действий
  • ThreadPoolExecutor.execute(Runnable) — очередь команд

Дополнительные возможности

  • Очередь команд: накопление и пакетное выполнение
  • История (undo/redo): хранение выполненных команд для отмены
  • Логирование: запись всех выполненных операций
  • Транзакции: выполнение группы команд атомарно
🚦 State (Состояние)

Краткий ответ: State — поведенческий паттерн, позволяющий объекту изменять своё поведение при изменении внутреннего состояния. Каждое состояние знает, что делать и в какое состояние перейти дальше.

Когда использовать

  • есть жизненный цикл объекта;
  • поведение зависит от текущего состояния;
  • много условий вида if (state == NEW) ... else if (state == PAID) ...

Пример: жизненный цикл заказа

interface OrderState {
    void next(Order order);
    void cancel(Order order);
    String getStatus();
}

class NewState implements OrderState {
    public void next(Order order) { order.setState(new PaidState()); }
    public void cancel(Order order) { order.setState(new CancelledState()); }
    public String getStatus() { return "NEW"; }
}

class PaidState implements OrderState {
    public void next(Order order) { order.setState(new ShippedState()); }
    public void cancel(Order order) {
        System.out.println("Возврат средств...");
        order.setState(new CancelledState());
    }
    public String getStatus() { return "PAID"; }
}

class ShippedState implements OrderState {
    public void next(Order order) { order.setState(new DeliveredState()); }
    public void cancel(Order order) {
        System.out.println("Заказ уже отправлен, отмена невозможна");
    }
    public String getStatus() { return "SHIPPED"; }
}

class DeliveredState implements OrderState {
    public void next(Order order) {
        System.out.println("Заказ уже доставлен");
    }
    public void cancel(Order order) {
        System.out.println("Заказ доставлен, отмена невозможна");
    }
    public String getStatus() { return "DELIVERED"; }
}

class CancelledState implements OrderState {
    public void next(Order order) { System.out.println("Отменённый заказ"); }
    public void cancel(Order order) { System.out.println("Уже отменён"); }
    public String getStatus() { return "CANCELLED"; }
}

class Order {
    private OrderState state = new NewState();

    void setState(OrderState state) { this.state = state; }
    void next() { state.next(this); }
    void cancel() { state.cancel(this); }
    String getStatus() { return state.getStatus(); }
}

Где используется

  • Workflow / State Machine — бизнес-процессы
  • Spring State Machine — управление состояниями в Spring
  • Игровые персонажи — стояние, бег, прыжок, атака
  • TCP-соединения — CLOSED, LISTEN, ESTABLISHED
  • Банкомат — ожидание карты, ввод PIN, выбор операции

State vs Strategy

StrategyState
Решает задачу выбора алгоритмаИзменяет поведение по состоянию
Стратегии независимыСостояния связаны переходами
Выбирается клиентомМеняется самим объектом
Нет жизненного циклаЕсть жизненный цикл объекта

Мнемоника: Strategy = "Как выполнить?", State = "В каком я состоянии?"

📚 Iterator (Итератор)

Краткий ответ: Iterator — поведенческий паттерн, предоставляющий единый способ последовательного обхода элементов коллекции без раскрытия её внутренней реализации. В Java реализован интерфейсом Iterator.

Основные методы

public interface Iterator<E> {
    boolean hasNext();  // есть ли следующий элемент
    E next();           // следующий элемент + сдвиг курсора
    default void remove(); // удаление (необязательно)
}

Почему Iterator лучше обхода по индексам

Для ArrayList get(i) — O(1). Для LinkedList get(i) — O(n), цикл превращается в O(n²). Iterator скрывает особенности реализации и обеспечивает эффективный обход для любой коллекции.

Iterable и цикл for-each

// for-each — синтаксический сахар над Iterator
for (String s : list) { System.out.println(s); }
// Компилятор преобразует в:
Iterator<String> it = list.iterator();
while (it.hasNext()) { String s = it.next(); ... }

Fail-Fast vs Fail-Safe

  • Fail-Fast: ArrayList, HashSet. При изменении коллекции извне — ConcurrentModificationException.
  • Fail-Safe: CopyOnWriteArrayList, ConcurrentHashMap. Работают по снимку данных, не бросают исключение.

Другие виды итераторов

  • ListIterator: только для List, умеет идти назад (previous), изменять (set), добавлять (add).
  • Spliterator (Java 8): для Stream API и параллельной обработки, эффективно разбивает коллекцию на части.

Iterator vs Iterable

Iterable — объект умеет создавать итератор (метод iterator()). Iterator — выполняет обход (hasNext(), next()). Коллекция реализует Iterable, а сам обход выполняет Iterator.

📋 Template Method (Шаблонный метод)

Краткий ответ: Template Method определяет скелет алгоритма в базовом классе, оставляя реализацию некоторых шагов подклассам. Подклассы могут переопределять шаги, не меняя общей структуры алгоритма.

Пример: экспорт данных

abstract class DataExporter {
    // Шаблонный метод — final, чтобы подклассы не могли изменить порядок
    public final void export() {
        connect();
        fetchData();
        writeFile();
        close();
        System.out.println("Экспорт завершён");
    }

    void connect() { System.out.println("Подключение к источнику"); }
    abstract void fetchData(); // различается в подклассах
    void writeFile() { System.out.println("Запись файла"); }
    void close() { System.out.println("Закрытие соединения"); }
}

class CsvExporter extends DataExporter {
    void fetchData() { System.out.println("Получение данных в CSV"); }
}

class JsonExporter extends DataExporter {
    void fetchData() { System.out.println("Получение данных в JSON"); }
}

Где используется в Java

  • AbstractList — get(), size() абстрактные, add() и remove() определены через них
  • JdbcTemplate — шаблон для работы с БД
  • HttpServlet — doGet(), doPost() переопределяются, сервлет управляет жизненным циклом
  • InputStream — read() определен через read(byte[], int, int)

Принцип Голливуда

"Не звоните нам — мы вам позвоним". Базовый класс вызывает методы подклассов, а не наоборот. Инверсия управления на уровне классов.

⛓️ Chain of Responsibility (Цепочка обязанностей)

Краткий ответ: Chain of Responsibility передаёт запрос по цепочке обработчиков. Каждый обработчик решает, может ли он обработать запрос, и либо обрабатывает, либо передаёт дальше.

Пример: цепочка валидации

abstract class Validator {
    protected Validator next;

    public Validator setNext(Validator next) {
        this.next = next;
        return next; // fluent API
    }

    public abstract boolean validate(Request request);
}

class AuthValidator extends Validator {
    public boolean validate(Request request) {
        if (!request.isAuthenticated()) {
            System.out.println("Ошибка аутентификации");
            return false;
        }
        System.out.println("Аутентификация пройдена");
        return next == null || next.validate(request);
    }
}

class RoleValidator extends Validator {
    public boolean validate(Request request) {
        if (!request.hasRole("ADMIN")) {
            System.out.println("Недостаточно прав");
            return false;
        }
        System.out.println("Права подтверждены");
        return next == null || next.validate(request);
    }
}

class ThrottleValidator extends Validator {
    private int requestCount = 0;
    public boolean validate(Request request) {
        if (++requestCount > 100) {
            System.out.println("Превышен лимит запросов");
            return false;
        }
        System.out.println("Лимит запросов OK");
        return next == null || next.validate(request);
    }
}

// Использование: строим цепочку
Validator chain = new AuthValidator();
chain.setNext(new RoleValidator()).setNext(new ThrottleValidator());
chain.validate(request);

Где используется в Java

  • Servlet Filters — цепочка фильтров HTTP-запросов
  • Spring Security Filter Chain — цепочка фильтров безопасности
  • Logback / Log4j — цепочка логгеров (логгер → родитель → родитель)
  • try-catch — исключения передаются по цепочке catch блоков

Преимущества

  • Ослабляет связанность — отправитель не знает, кто обработает запрос
  • Гибкость — можно динамически менять цепочку
  • Каждый обработчик выполняет только свою задачу (SRP)
🕊️ Mediator (Посредник)

Краткий ответ: Mediator централизует взаимодействие между компонентами, уменьшая их связанность. Вместо того чтобы компоненты общались напрямую, они общаются через посредника.

Проблема без Mediator

// Все компоненты знают друг о друге — спагетти зависимостей
class Button {
    private TextField textField;
    private ListBox listBox;
    public void click() {
        textField.clear();
        listBox.refresh();
    }
}

Решение с Mediator

interface Mediator {
    void notify(Component sender, String event);
}

// Конкретный посредник — диалоговое окно
class Dialog implements Mediator {
    private Button okButton;
    private TextField textField;
    private ListBox listBox;

    public void notify(Component sender, String event) {
        if (sender == okButton && event.equals("click")) {
            textField.clear();
            listBox.refresh();
        }
        if (sender == textField && event.equals("change")) {
            listBox.filter(textField.getText());
        }
    }
}

abstract class Component {
    protected Mediator mediator;
    public Component(Mediator mediator) { this.mediator = mediator; }
}

class Button extends Component {
    public void click() { mediator.notify(this, "click"); }
}

class TextField extends Component {
    private String text;
    public void onChange() { mediator.notify(this, "change"); }
}

Где используется в Java

  • java.util.Timer — посредник между задачами и временем выполнения
  • Spring MVC DispatcherServlet — посредник между контроллерами, видами и моделями
  • Event Bus / Message Broker — централизованный обмен сообщениями
  • Swing Dialog — диалоговое окно как посредник для своих компонентов

Преимущества и недостатки

Плюсы: устраняет связанность между компонентами, централизует управление, упрощает добавление новых компонентов.

Минусы: посредник может стать God Object — слишком много логики в одном классе.

Mediator vs Observer

Mediator — централизованное управление взаимодействием. Observer — децентрализованное уведомление о событиях.
